# Book dental appointments via chat using OpenAI, Qdrant, and Google Calendar

### 1. Workflow Overview

This workflow implements an automated chat-based dental clinic receptionist. It allows patients to ask questions based on approved internal documents, check real-time availability via Google Calendar, and book appointments directly through a secure chat interface. Additionally, administrators can upload text documents to update the clinic's knowledge base.

The logic is divided into three primary execution branches:
- **1.1 Chat and Inquiry Processing:** Handles patient interactions via chat, leverages an OpenAI language model with conversation memory, retrieves clinic facts from a Qdrant vector store, and exposes tools to check availability and book appointments.
- **1.2 Administrative Knowledge Upload:** Processes administrative text file uploads, validates the content, splits it into chunks, generates vector embeddings using OpenAI, and indexes the information into Qdrant.
- **1.3 Calendar API Backend:** Serves as a protected webhook endpoint that validates incoming requests, queries Google Calendar's free/busy schedule using native date-time calculations, handles slot generation, creates events, and verifies booking results.

### 2. Block-by-Block Analysis

#### Block 1: Chat and Inquiry Processing
- **Overview:** Receives messages from the chat interface, configures the base URL for internal API calls, drives an OpenAI-powered agent with memory, and allows it to query Qdrant and execute calendar availability checks or bookings.
- **Nodes Involved:**
  - `Chat with Dental Receptionist`
  - `Configure Chat Endpoint`
  - `Dental Receptionist`
  - `Receptionist OpenAI Model`
  - `Conversation Memory`
  - `clinic_knowledge`
  - `Search Embeddings`
  - `calendar_availability`
  - `book_appointment`

- **Node Details:**
  - **Chat with Dental Receptionist**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.chatTrigger` (Chat Trigger) — Entry point for chat interactions.
    - *Configuration:* Public option disabled (`false`).
    - *Inputs/Outputs:* Input: None; Output: Triggers `Configure Chat Endpoint`.
    - *Edge Cases:* Unauthenticated access if exposed publicly without proper instance-level controls.
  - **Configure Chat Endpoint**
    - *Type and Role:* `n8n-nodes-base.code` (Code Node) — Injects the n8n instance base URL into the workflow item data.
    - *Configuration:* JavaScript code defining `baseUrl` and appending the webhook path (`/webhook/dental-receptionist-calendar-v1`).
    - *Inputs/Outputs:* Input: `Chat with Dental Receptionist`; Output: `Dental Receptionist`.
    - *Edge Cases:* Incorrect base URL string will break downstream tool calls.
  - **Dental Receptionist**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.agent` (AI Agent) — Core conversational agent orchestrating system prompts, memory, tools, and the language model.
    - *Configuration:* System prompt restricts answers strictly to retrieved knowledge, mandates handling of UTC dates, and enforces explicit patient confirmation before booking. Max iterations set to 6.
    - *Inputs/Outputs:* Inputs: `Configure Chat Endpoint`, `Receptionist OpenAI Model`, `Conversation Memory`, `clinic_knowledge`, `calendar_availability`, `book_appointment`; Output: Sends responses back to the chat trigger context.
    - *Edge Cases:* Hallucinations or bypassing constraints if prompt injection occurs via user messages or retrieved data.
  - **Receptionist OpenAI Model**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.lmChatOpenAi` (OpenAI Chat Model) — Provides the LLM backbone.
    - *Configuration:* Model set to `gpt-4.1-mini`.
    - *Inputs/Outputs:* Input: None (connected to agent); Output: `Dental Receptionist`.
    - *Edge Cases:* API rate limits, authentication failures, or upstream OpenAI outages.
  - **Conversation Memory**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.memoryBufferWindow` (Window Buffer Memory) — Maintains short-term conversational context.
    - *Configuration:* Context window length set to 25 messages.
    - *Inputs/Outputs:* Input: None; Output: `Dental Receptionist`.
    - *Edge Cases:* Simple memory uses session-based tracking and is unsuited for multi-instance queue-mode deployments without persistent storage.
  - **clinic_knowledge**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.vectorStoreQdrant` (Qdrant Vector Store) — Tool node allowing the agent to query the vector database.
    - *Configuration:* Mode set to `retrieve-as-tool`; collection ID set to `dental_clinic_knowledge`.
    - *Inputs/Outputs:* Inputs: `Dental Receptionist`, `Search Embeddings`; Output: Connected to agent as a tool.
    - *Edge Cases:* Qdrant connectivity drops or collection mismatch errors.
  - **Search Embeddings**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.embeddingsOpenAi` (OpenAI Embeddings) — Generates vector embeddings for search queries.
    - *Configuration:* Model set to `text-embedding-3-small`.
    - *Inputs/Outputs:* Input: Connected to `clinic_knowledge`; Output: `clinic_knowledge`.
    - *Edge Cases:* Embedding dimension mismatch with Qdrant collection (requires 1536 dimensions).
  - **calendar_availability**
    - *Type and Role:* `n8n-nodes-base.httpRequestTool` (HTTP Request Tool) — Exposes calendar availability checking as an agent tool.
    - *Configuration:* POST request to `calendarApiUrl` with action `availability` and extracted `date`. Uses Generic HTTP Header Auth (`X-Clinic-Key`).
    - *Inputs/Outputs:* Inputs: `Dental Receptionist`, `Configure Chat Endpoint`; Output: Connected to agent as a tool.
    - *Edge Cases:* Timeouts (60s limit) or network errors reaching the webhook endpoint.
  - **book_appointment**
    - *Type and Role:* `n8n-nodes-base.httpRequestTool` (HTTP Request Tool) — Exposes appointment booking as an agent tool.
    - *Configuration:* POST request to `calendarApiUrl` with action `book`, passing `date`, `time`, `name`, `email`, and `confirmed` boolean. Uses Generic HTTP Header Auth (`X-Clinic-Key`).
    - *Inputs/Outputs:* Inputs: `Dental Receptionist`, `Configure Chat Endpoint`; Output: Connected to agent as a tool.
    - *Edge Cases:* Missing or invalid confirmation parameters passed by the model.

#### Block 2: Administrative Knowledge Upload
- **Overview:** Provides a secured form for administrators to upload plain-text documents containing clinic details, validates the text length, chunks it, embeds it, and stores it in Qdrant.
- **Nodes Involved:**
  - `Upload Clinic Knowledge`
  - `Extract Knowledge Text`
  - `Validate Knowledge Text`
  - `Index Clinic Knowledge`
  - `Load Clinic Document`
  - `Split Knowledge into Chunks`
  - `Upload Embeddings`

- **Node Details:**
  - **Upload Clinic Knowledge**
    - *Type and Role:* `n8n-nodes-base.formTrigger` (Form Trigger) — Webhook form allowing file uploads.
    - *Configuration:* Requires an administrator-only `.txt` file upload (max 200,000 characters). Secured using HTTP Basic Auth.
    - *Inputs/Outputs:* Input: None; Output: `Extract Knowledge Text`.
    - *Edge Cases:* Uploading non-text files or exceeding character size limits.
  - **Extract Knowledge Text**
    - *Type and Role:* `n8n-nodes-base.extractFromFile` (Extract from File) — Parses the binary file content into text.
    - *Configuration:* Operation set to text using UTF-8 encoding on the `File` binary property.
    - *Inputs/Outputs:* Input: `Upload Clinic Knowledge`; Output: `Validate Knowledge Text`.
    - *Edge Cases:* Corrupted file binaries or unsupported text encodings.
  - **Validate Knowledge Text**
    - *Type and Role:* `n8n-nodes-base.code` (Code Node) — Validates that extracted text is non-empty and within allowable size limits.
    - *Configuration:* Throws an error if text is empty or longer than 200,000 characters.
    - *Inputs/Outputs:* Input: `Extract Knowledge Text`; Output: `Index Clinic Knowledge`.
    - *Edge Cases:* Script execution failure on malformed text strings.
  - **Index Clinic Knowledge**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.vectorStoreQdrant` (Qdrant Vector Store) — Inserts processed document chunks into Qdrant.
    - *Configuration:* Mode set to `insert`; collection ID set to `dental_clinic_knowledge`.
    - *Inputs/Outputs:* Inputs: `Validate Knowledge Text`, `Load Clinic Document`, `Upload Embeddings`; Output: None (terminal node for upload flow).
    - *Edge Cases:* Qdrant insertion failures or network timeouts.
  - **Load Clinic Document**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.documentDefaultDataLoader` (Default Data Loader) — Loads text data into the vector ingestion pipeline.
    - *Configuration:* Data type set to JSON expression data (`{{ $json.text }}`).
    - *Inputs/Outputs:* Input: `Split Knowledge into Chunks`; Output: `Index Clinic Knowledge`.
    - *Edge Cases:* Expression evaluation errors.
  - **Split Knowledge into Chunks**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.textSplitterTokenSplitter` (Token Text Splitter) — Breaks documents into smaller chunks for vectorization.
    - *Configuration:* Chunk size set to 500 tokens with a 50-token overlap.
    - *Inputs/Outputs:* Input: None; Output: `Load Clinic Document`.
    - *Edge Cases:* Extremely short texts causing splitting edge cases.
  - **Upload Embeddings**
    - *Type and Role:* `@n8n/n8n-nodes-langchain.embeddingsOpenAi` (OpenAI Embeddings) — Generates vector representations for document chunks.
    - *Configuration:* Model set to `text-embedding-3-small`.
    - *Inputs/Outputs:* Input: None; Output: `Index Clinic Knowledge`.
    - *Edge Cases:* OpenAI API authentication failures or rate limits.

#### Block 3: Calendar API Backend
- **Overview:** Receives webhook requests for schedule availability or appointment booking, validates inputs, queries Google Calendar free/busy endpoints, checks for slot conflicts, creates calendar events, and returns structured responses.
- **Nodes Involved:**
  - `Calendar API`
  - `Configure and Validate Calendar Request`
  - `Request Valid`
  - `Check Google Calendar Busy Times`
  - `Calculate Available Slots`
  - `Slot Ready to Book`
  - `Create Confirmed Calendar Appointment`
  - `Verify Booking Result`
  - `Return Calendar Result`

- **Node Details:**
  - **Calendar API**
    - *Type and Role:* `n8n-nodes-base.webhook` (Webhook) — Entry point for internal API calls.
    - *Configuration:* Path set to `dental-receptionist-calendar-v1`, method POST, authenticated via Header Auth. Response mode set to use the Respond to Webhook node.
    - *Inputs/Outputs:* Input: None; Output: `Configure and Validate Calendar Request`.
    - *Edge Cases:* Missing or invalid authentication headers resulting in rejected requests.
  - **Configure and Validate Calendar Request**
    - *Type and Role:* `n8n-nodes-base.code` (Code Node) — Validates request payloads, checks working days, opening hours, lead times, and constructs Google free/busy queries.
    - *Configuration:* Hardcoded configuration parameters (calendar ID, timezone, 09:00–17:00 working hours, 30-minute slots, 60-min lead time, 90-day booking horizon).
    - *Inputs/Outputs:* Input: `Calendar API`; Output: `Request Valid`.
    - *Edge Cases:* Invalid JSON payloads, past dates, unconfigured calendar IDs, or ambiguous local times.
  - **Request Valid**
    - *Type and Role:* `n8n-nodes-base.if` (If Node) — Branches execution based on whether the request validation succeeded.
    - *Configuration:* Evaluates `{{ $json.valid }}` (boolean).
    - *Inputs/Outputs:* Input: `Configure and Validate Calendar Request`; Outputs: True branch to `Check Google Calendar Busy Times`, False branch to `Return Calendar Result`.
    - *Edge Cases:* Unhandled boolean expressions.
  - **Check Google Calendar Busy Times**
    - *Type and Role:* `n8n-nodes-base.httpRequest` (HTTP Request) — Queries the Google Calendar FreeBusy API.
    - *Configuration:* POST request to `https://www.googleapis.com/calendar/v3/freeBusy` using Google Calendar OAuth2 credentials. Error handling set to continue regular output.
    - *Inputs/Outputs:* Input: `Request Valid` (True); Output: `Calculate Available Slots`.
    - *Edge Cases:* Google API token expiration, insufficient permissions, or API rate limiting.
  - **Calculate Available Slots**
    - *Type and Role:* `n8n-nodes-base.code` (Code Node) — Filters out busy periods from generated slots and prepares event payloads if booking is requested.
    - *Configuration:* JavaScript logic compares calendar busy blocks against generated clinic slots and constructs a deterministic event ID (`dental` + timestamp hex).
    - *Inputs/Outputs:* Input: `Check Google Calendar Busy Times`; Output: `Slot Ready to Book`.
    - *Edge Cases:* Google Calendar returning malformed busy intervals or API errors (status code != 200).
  - **Slot Ready to Book**
    - *Type and Role:* `n8n-nodes-base.if` (If Node) — Determines if the request is ready to execute a calendar booking insertion.
    - *Configuration:* Evaluates `{{ $json.readyToBook }}` (boolean).
    - *Inputs/Outputs:* Input: `Calculate Available Slots`; Outputs: True branch to `Create Confirmed Calendar Appointment`, False branch to `Return Calendar Result`.
    - *Edge Cases:* Unmet booking prerequisites routing through the false branch.
  - **Create Confirmed Calendar Appointment**
    - *Type and Role:* `n8n-nodes-base.httpRequest` (HTTP Request) — Creates the appointment event in Google Calendar.
    - *Configuration:* POST request to Google Calendar API events endpoint using OAuth2 credentials. Query parameter `sendUpdates=all` requests email invitations. Error handling set to continue regular output.
    - *Inputs/Outputs:* Input: `Slot Ready to Book` (True); Output: `Verify Booking Result`.
    - *Edge Cases:* 409 Conflict errors due to simultaneous bookings or calendar permission restrictions.
  - **Verify Booking Result**
    - *Type and Role:* `n8n-nodes-base.code` (Code Node) — Inspects the API response from Google Calendar to confirm successful event creation.
    - *Configuration:* Checks for successful HTTP status codes (2xx) and presence of an event ID.
    - *Inputs/Outputs:* Input: `Create Confirmed Calendar Appointment`; Output: `Return Calendar Result`.
    - *Edge Cases:* Undelivered responses or unknown API outcomes requiring manual staff review.
  - **Return Calendar Result**
    - *Type and Role:* `n8n-nodes-base.respondToWebhook` (Respond to Webhook) — Sends the final HTTP response back to the caller.
    - *Configuration:* Responds with JSON data and dynamic response code matching `{{ $json.httpStatus }}`.
    - *Inputs/Outputs:* Inputs: `Request Valid` (False), `Slot Ready to Book` (False), `Verify Booking Result`; Output: None (terminal node).
    - *Edge Cases:* Response timeouts if upstream execution hangs.

### 4. Reproducing the Workflow from Scratch

1. **Create the Workflow and Sticky Notes:**
   - Create a new n8n workflow.
   - (Optional) Add organizational sticky notes referencing setup instructions, calendar configurations, and verification checklists as detailed in the source definitions.

2. **Build the Chat & Agent Branch:**
   - **Step 2.1:** Create a `Chat Trigger` (`@n8n/n8n-nodes-langchain.chatTrigger`) named `Chat with Dental Receptionist`. Set public options to `false`.
   - **Step 2.2:** Create a `Code` node (`n8n-nodes-base.code`) named `Configure Chat Endpoint`. Set the JavaScript code to map items, adding `calendarApiUrl` using your n8n base URL and path `/webhook/dental-receptionist-calendar-v1`. Connect `Chat with Dental Receptionist` to it.
   - **Step 2.3:** Create an `AI Agent` (`@n8n/n8n-nodes-langchain.agent`) named `Dental Receptionist`. Configure its system message to handle timezone awareness, Qdrant document retrieval restrictions, and strict booking confirmation steps. Connect `Configure Chat Endpoint` to its main input.
   - **Step 2.4:** Create an OpenAI Chat Model node (`@n8n/n8n-nodes-langchain.lmChatOpenAi`) named `Receptionist OpenAI Model` using model `gpt-4.1-mini`. Connect it to the agent's language model input.
   - **Step 2.5:** Create a Window Buffer Memory node (`@n8n/n8n-nodes-langchain.memoryBufferWindow`) named `Conversation Memory` with a context window length of 25. Connect it to the agent's memory input.
   - **Step 2.6:** Create a Qdrant Vector Store node (`@n8n/n8n-nodes-langchain.vectorStoreQdrant`) named `clinic_knowledge`. Set mode to `retrieve-as-tool`, description to "Use this tool get details of clinic", and collection ID to `dental_clinic_knowledge`. Connect it to the agent's tool input.
   - **Step 2.7:** Create an OpenAI Embeddings node (`@n8n/n8n-nodes-langchain.embeddingsOpenAi`) named `Search Embeddings` using model `text-embedding-3-small`. Connect it to the embeddings input of `clinic_knowledge`.
   - **Step 2.8:** Create an HTTP Request Tool node (`n8n-nodes-base.httpRequestTool`) named `calendar_availability`. Set URL to `={{ $('Configure Chat Endpoint').item.json.calendarApiUrl }}`, method to `POST`, authentication to Generic Credential Type (HTTP Header Auth, name `X-Clinic-Key`), and configure body parameters for `action` (`availability`) and `date` (`={{ $fromAI(...) }}`). Connect it as an agent tool.
   - **Step 2.9:** Create an HTTP Request Tool node (`n8n-nodes-base.httpRequestTool`) named `book_appointment`. Set URL to `={{ $('Configure Chat Endpoint').item.json.calendarApiUrl }}`, method to `POST`, authentication to Generic Credential Type (HTTP Header Auth, name `X-Clinic-Key`), and configure body parameters for `action` (`book`), `date`, `time`, `name`, `email`, and `confirmed`. Connect it as an agent tool.

3. **Build the Knowledge Upload Branch:**
   - **Step 3.1:** Create a Form Trigger node (`n8n-nodes-base.formTrigger`) named `Upload Clinic Knowledge`. Set authentication to Basic Auth, configure form fields for a required file upload (`.txt`), and set form description for administrators.
   - **Step 3.2:** Create an Extract from File node (`n8n-nodes-base.extractFromFile`) named `Extract Knowledge Text`. Set operation to text with UTF-8 encoding on property `File`. Connect `Upload Clinic Knowledge` to it.
   - **Step 3.3:** Create a Code node (`n8n-nodes-base.code`) named `Validate Knowledge Text` to ensure text is non-empty and under 200,000 characters. Connect `Extract Knowledge Text` to it.
   - **Step 3.4:** Create a Text Splitter Token Splitter node (`@n8n/n8n-nodes-langchain.textSplitterTokenSplitter`) named `Split Knowledge into Chunks` with chunk size 500 and overlap 50.
   - **Step 3.5:** Create a Default Data Loader node (`@n8n/n8n-nodes-langchain.documentDefaultDataLoader`) named `Load Clinic Document` pointing to `{{ $json.text }}`. Connect `Split Knowledge into Chunks` to it.
   - **Step 3.6:** Create an OpenAI Embeddings node (`@n8n/n8n-nodes-langchain.embeddingsOpenAi`) named `Upload Embeddings` using model `text-embedding-3-small`.
   - **Step 3.7:** Create a Qdrant Vector Store node (`@n8n/n8n-nodes-langchain.vectorStoreQdrant`) named `Index Clinic Knowledge`. Set mode to `insert` and collection ID to `dental_clinic_knowledge`. Connect `Validate Knowledge Text`, `Load Clinic Document`, and `Upload Embeddings` to it.

4. **Build the Calendar API Backend Branch:**
   - **Step 4.1:** Create a Webhook node (`n8n-nodes-base.webhook`) named `Calendar API`. Set path to `dental-receptionist-calendar-v1`, method to `POST`, response mode to `responseNode`, and authentication to Header Auth (`X-Clinic-Key`).
   - **Step 4.2:** Create a Code node (`n8n-nodes-base.code`) named `Configure and Validate Calendar Request`. Define the configuration object (`calendarId`, `timezone`, opening/closing hours, slot duration, working days, lead time, advance days) and validation logic. Connect `Calendar API` to it.
   - **Step 4.3:** Create an If node (`n8n-nodes-base.if`) named `Request Valid` evaluating `{{ $json.valid }}`. Connect `Configure and Validate Calendar Request` to it.
   - **Step 4.4:** Create an HTTP Request node (`n8n-nodes-base.httpRequest`) named `Check Google Calendar Busy Times`. Set URL to `https://www.googleapis.com/calendar/v3/freeBusy`, method to `POST`, body type to JSON (`{{ $json.freebusyRequest }}`), and authenticate via Google Calendar OAuth2 API. Set `onError` to `continueRegularOutput`. Connect the True branch of `Request Valid` to it.
   - **Step 4.5:** Create a Code node (`n8n-nodes-base.code`) named `Calculate Available Slots` to filter free/busy intervals and generate booking event payloads. Connect `Check Google Calendar Busy Times` to it.
   - **Step 4.6:** Create an If node (`n8n-nodes-base.if`) named `Slot Ready to Book` evaluating `{{ $json.readyToBook }}`. Connect `Calculate Available Slots` to it.
   - **Step 4.7:** Create an HTTP Request node (`n8n-nodes-base.httpRequest`) named `Create Confirmed Calendar Appointment`. Set URL dynamically to Google Calendar events endpoint, method to `POST`, specify JSON body (`{{ $json.event }}`), query parameter `sendUpdates=all`, and authenticate via Google Calendar OAuth2 API. Set `onError` to `continueRegularOutput`. Connect the True branch of `Slot Ready to Book` to it.
   - **Step 4.8:** Create a Code node (`n8n-nodes-base.code`) named `Verify Booking Result` to inspect the Google Calendar response. Connect `Create Confirmed Calendar Appointment` to it.
   - **Step 4.9:** Create a Respond to Webhook node (`n8n-nodes-base.respondToWebhook`) named `Return Calendar Result`. Set response code to `={{ $json.httpStatus }}` and response body to `={{ $json.result }}`. Connect the False branch of `Request Valid`, False branch of `Slot Ready to Book`, and `Verify Booking Result` to this node.

5. **Credential & Configuration Checklist:**
   - Connect valid OpenAI API credentials to all OpenAI model and embedding nodes.
   - Connect Qdrant credentials to both Qdrant vector store nodes and ensure a collection named `dental_clinic_knowledge` (1536 dimensions, Cosine distance) exists.
   - Connect Google Calendar OAuth2 credentials to both Google HTTP Request nodes.
   - Create an HTTP Header Auth credential named `X-Clinic-Key` with a strong secret value, and assign it to the `Calendar API` webhook, `calendar_availability` tool, and `book_appointment` tool.
   - Assign HTTP Basic Auth credentials to `Upload Clinic Knowledge`.
   - Update `Configure and Validate Calendar Request` with your specific Google Calendar ID and clinic timezone/hours.
