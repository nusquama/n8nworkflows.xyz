# Screen and score resumes from Gmail with Parseur, Groq, and Google Sheets

### 1. Workflow Overview

This workflow automates the intake, parsing, AI evaluation, and logging of candidate resumes received via email. It is designed for recruiters and HR teams to process applications received in a Gmail inbox, extract structured data from attachments, evaluate candidate fit using an LLM, archive the original documents in Google Drive, and maintain a centralized tracking sheet in Google Sheets.

The workflow logic is grouped into three main functional blocks:
- **1.1 Document Ingestion & Extraction:** Monitors Gmail for incoming applications with attachments, downloads the raw files, and submits them to Parseur for OCR and field extraction.
- **1.2 Validation & AI Candidate Scoring:** Validates the extraction results, formats file naming conventions, and queries a Groq language model to generate a numerical fit score (1–10) based on candidate attributes.
- **1.3 Storage & Candidate Logging:** Downloads the raw resume file, uploads it to Google Drive with a standardized name, and appends or updates the candidate record in Google Sheets.

### 2. Block-by-Block Analysis

#### 2.1 Document Ingestion & Extraction
This block handles the polling of the Gmail inbox, fetches specific emails containing resume attachments, and initiates the document parsing process via the Parseur API.

- **New Resume Email Trigger**
  - **Type & Technical Role:** `n8n-nodes-base.gmailTrigger` (Trigger) — Polls a Gmail inbox every minute for emails matching specific attachment filters.
  - **Configuration Choices:** Filters emails using `has:attachment (filename:pdf OR filename:doc OR filename:docx)`. Sets polling interval to every minute. Configures attachment prefix name as `attachment_`.
  - **Key Expressions / Variables:** Uses fixed filter strings.
  - **Input / Output Connections:** Input: None (Trigger) | Output: `Fetch Email & Attachment`.
  - **Edge Cases & Failure Types:** Authentication token expiration; failure to catch specific non-standard attachment extensions.

- **Fetch Email & Attachment**
  - **Type & Technical Role:** `n8n-nodes-base.gmail` (Action) — Retrieves the full message content and downloads its binary attachments.
  - **Configuration Choices:** Operation set to `get`, `downloadAttachments` enabled.
  - **KeyExpressions / Variables:** `={{ $json.id }}` references the email ID from the trigger.
  - **Input / Output Connections:** Input: `New Resume Email Trigger` | Output: `Send Resume to Parseur`.
  - **Edge Cases & Failure Types:** Missing attachment binaries; API rate limits from Gmail.

- **Send Resume to Parseur**
  - **Type & Technical Role:** `n8n-nodes-parseur.parseur` (Action) — Submits the extracted binary resume file to Parseur for parsing.
  - **Configuration Choices:** `parserId` set to `200661`. `binaryPropertyName` mapped to `=attachment_0`.
  - **Key Expressions / Variables:** `=attachment_0`.
  - **Input / Output Connections:** Input: `Fetch Email & Attachment` | Output: `Wait for Parseur Processing`.
  - **Edge Cases & Failure Types:** Invalid Parser ID; unsupported file formats causing parsing failure.

- **Wait for Parseur Processing**
  - **Type & Technical Role:** `n8n-nodes-base.wait` (Flow Control) — Pauses execution to allow Parseur sufficient time to process the uploaded document.
  - **Configuration Choices:** Wait amount set to `25` seconds.
  - **Key Expressions / Variables:** None.
  - **Input / Output Connections:** Input: `Send Resume to Parseur` | Output: `Get Parsed Document Metadata`.
  - **Edge Cases & Failure Types:** If Parseur processing takes longer than 25 seconds, subsequent steps may pull incomplete data.

- **Get Parsed Document Metadata**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (Action) — Queries the Parseur API to retrieve metadata for the most recently parsed document.
  - **Configuration Choices:** Sends a GET request to `https://api.parseur.com/parser/200661/document_set?last_document_only=true` using generic HTTP Header authentication. Response format set to JSON.
  - **Key Expressions / Variables:** None.
  - **Input / Output Connections:** Input: `Wait for Parseur Processing` | Output: `Get Extracted Candidate Data`.
  - **Edge Cases & Failure Types:** HTTP 401/403 due to invalid API headers; empty result sets if parsing failed entirely.

- **Get Extracted Candidate Data**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (Action) — Downloads the structured JSON extraction payload generated by Parseur.
  - **Configuration Choices:** Sends a GET request using the JSON download URL obtained from the previous metadata step. Uses generic HTTP Header authentication.
  - **Key Expressions / Variables:** `={{ $json.results[0].json_download_url }}`
  - **Input / Output Connections:** Input: `Get Parsed Document Metadata` | Output: `Check Candidate Name Exists`.
  - **Edge Cases & Failure Types:** Broken download links; network timeout.

#### 2.2 Validation & AI Candidate Scoring
This block validates that candidate extraction was successful, generates standardized naming variables, and queries an LLM via LangChain to score the candidate.

- **Check Candidate Name Exists**
  - **Type & Technical Role:** `n8n-nodes-base.if` (Flow Control) — Branching node that checks whether the extracted candidate name is present.
  - **Configuration Choices:** Evaluates if `{{ $json["Candidate Name"] }}` is not equal to an empty string `""`.
  - **Key Expressions / Variables:** `={{ $json["Candidate Name"] }}`
  - **Input / Output Connections:** Input: `Get Extracted Candidate Data` | Outputs: True branch goes to `Generate Filename & Document ID`; False branch goes to `Skip - Invalid/Empty Extraction`.
  - **Edge Cases & Failure Types:** Unexpected null values or formatting variations representing empty states.

- **Skip - Invalid/Empty Extraction**
  - **Type & Technical Role:** `n8n-nodes-base.noOp` (Flow Control / Termination) — Terminal or pass-through node for invalid records where candidate extraction failed.
  - **Configuration Choices:** Default no-operation configuration.
  - **Key Expressions / Variables:** None.
  - **Input / Output Connections:** Input: `Check Candidate Name Exists` (False branch) | Output: None.
  - **Edge Cases & Failure Types:** None.

- **Generate Filename & Document ID**
  - **Type & Technical Role:** `n8n-nodes-base.code` (Data Transformation) — Executes custom JavaScript to normalize candidate names and roles into a clean base filename and extract the document ID.
  - **Configuration Choices:** JavaScript processing replacing whitespace with underscores.
  - **Key Expressions / Variables:** 
    ```javascript
    const candidateName = $json["Candidate Name"].replace(/\s+/g, "_");
    const positionRole = $json["Position Applied For"].replace(/\s+/g, "_");
    ```
  - **Input / Output Connections:** Input: `Check Candidate Name Exists` (True branch) | Output: `AI Fit Score Generator`.
  - **Edge Cases & Failure Types:** JavaScript runtime errors if expected properties are missing or undefined.

- **AI Fit Score Generator**
  - **Type & Technical Role:** `@n8n/n8n-nodes-langchain.agent` (AI / LLM Agent) — LangChain agent configured to evaluate candidate details and output a strict numerical fit score.
  - **Configuration Choices:** Prompt type set to define. Instructs the model to output *only* a number from 1 to 10 based on candidate name, position, experience, and key skills.
  - **Key Expressions / Variables:** Injects candidate attributes (`Candidate Name`, `Position Applied For`, `Years of Experience`, `Key Skills`) directly into the prompt template.
  - **Input / Output Connections:** Input: `Generate Filename & Document ID` (and linked to `Groq LLM (Scoring Model)`) | Output: `Download Original Resume File`.
  - **Edge Cases & Failure Types:** LLM returning conversational text instead of a pure number (which could impact downstream number parsing).

- **Groq LLM (Scoring Model)**
  - **Type & Technical Role:** `@n8n/n8n-nodes-langchain.lmChatGroq` (AI Model Sub-node) — Provides the Groq chat model integration for the AI Agent.
  - **Configuration Choices:** Model set to `openai/gpt-oss-20b`.
  - **Key Expressions / Variables:** None.
  - **Input / Output Connections:** Connected via `ai_languageModel` to `AI Fit Score Generator`.
  - **Edge Cases & Failure Types:** Groq API rate limits, invalid API keys, or model unavailability.

#### 2.3 Storage & Candidate Logging
This block retrieves the original resume file from Parseur, uploads it to Google Drive, and logs all candidate details, fit scores, and file references into Google Sheets.

- **Download Original Resume File**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (Action) — Downloads the raw original resume document using the URL provided by Parseur metadata.
  - **Configuration Choices:** Sends a GET request using generic HTTP Header authentication.
  - **Key Expressions / Variables:** `={{ $('Get Parsed Document Metadata').item.json.results[0].original_document_url }}`
  - **Input / Output Connections:** Input: `AI Fit Score Generator` | Output: `Upload Resume to Google Drive`.
  - **Edge Cases & Failure Types:** Expired or inaccessible original document URL.

- **Upload Resume to Google Drive**
  - **Type & Technical Role:** `n8n-nodes-base.googleDrive` (Action) — Uploads the downloaded binary resume file to a designated folder in Google Drive.
  - **Configuration Choices:** File name constructed dynamically using the base filename and binary file extension. Folder set to root (`root`).
  - **Key Expressions / Variables:** `={{ $('Generate Filename & Document ID').item.json.baseFilename }}.{{ $binary.data.fileExtension }}`
  - **Input / Output Connections:** Input: `Download Original Resume File` | Output: `Log Candidate to Tracker Sheet`.
  - **Edge Cases & Failure Types:** Insufficient Google Drive storage or permission errors.

- **Log Candidate to Tracker Sheet**
  - **Type & Technical Role:** `n8n-nodes-base.googleSheets` (Action) — Appends or updates the candidate tracker spreadsheet with extracted data, AI fit score, and Google Drive links.
  - **Configuration Choices:** Operation set to `appendOrUpdate`. Matching column set to `Email`. Maps spreadsheet columns (`Candidate Name`, `Email`, `Phone`, `Position Applied For`, `Years of Experience`, `Key Skills`, `Resume Link`, `Date Applied`, `Fit Score`).
  - **Key Expressions / Variables:** 
    - Email: `={{ $('Generate Filename & Document ID').item.json["Email"].replace(/^[:\s]+/, "") }}`
    - Phone: `={{ "'" + $('Generate Filename & Document ID').item.json["Phone"] }}`
    - Fit Score: `={{ Number($('AI Fit Score Generator').item.json.output) }}`
    - Resume Link: `={{ $json.webViewLink }}`
    - Date Applied: `={{ $now.format("yyyy-MM-dd") }}`
  - **Input / Output Connections:** Input: `Upload Resume to Google Drive` | Output: None (Terminal node).
  - **Edge Cases & Failure Types:** Spreadsheet schema mismatch, missing matching column values, or Google Sheets API quotas.

### 4. Reproducing the Workflow from Scratch

To rebuild this workflow manually in n8n, follow these step-by-step instructions:

1. **Create the Trigger Node (`New Resume Email Trigger`)**
   - Add a **Gmail Trigger** node.
   - Configure poll times to `every minute`.
   - Set filters query (`q`) to `has:attachment (filename:pdf OR filename:doc OR filename:docx)`.
   - Under options, set attachments prefix name to `attachment_`.
   - Connect Gmail OAuth2 credentials.

2. **Add Email Retrieval (`Fetch Email & Attachment`)**
   - Add a **Gmail** node.
   - Set operation to `Get` (`messageId`: `={{ $json.id }}`).
   - Enable `Download Attachments` in options.
   - Connect output of `New Resume Email Trigger` to this node.

3. **Configure Parseur Submission (`Send Resume to Parseur`)**
   - Add a **Parseur** node (`n8n-nodes-parseur.parseur`).
   - Set `Parser ID` to `200661`.
